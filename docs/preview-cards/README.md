# Preview card review images

- `zh-card.png`: server-generated fallback card for a Chinese report title.
- `en-card.png`: agent-authored `authoring/preview-card.svg` rendered by the Worker.
- `mixed-card.png`: mixed Chinese and English title.
- `emoji-card.png`: unsupported emoji replaced with a supported star glyph, avoiding a missing-glyph box.
- `link-preview-desktop.png` and `link-preview-phone.png`: illustrative before/after share-card layouts using the previous logo fallback and the new generated image. These are local mockups, not captures from a deployed social crawler.
- `profile-picks-1100.png` and `profile-picks-390.png`: actual local Worker and browser renders of the profile cards at desktop and phone widths.

The four cards were generated by `TDOC_PREVIEW_SAMPLES_DIR=docs/preview-cards node test/preview-cards.test.js` through the same `resvg-wasm` path used by the bundled Worker.
`npm run test:workerd` also renders a Chinese card in real workerd with the compiled WASM and font data modules (requires `npm ci`).
The profile screenshots came from `TDOC_UI_SHOTS=docs/preview-cards node test/profile-picks-ui.test.js`.

Card URLs include a content hash (`/d/<slug>/preview/v<N>-<hash>.png`), so replacing a version cannot leave social crawlers with an old image. Uploads queue rendering after the document metadata commits. A rejected author SVG uses the automatic card and returns `preview_warning`; renderer failures also try the automatic card. Re-publishing without a new SVG keeps the authored card. The CLI and Worker share `server/preview/validate-svg.js`.

Old documents show a matching 1200×630 SVG placeholder in My docs and profile cards until the explicit backfill runs. Social crawlers keep the existing PNG logo fallback until each public document has its generated PNG.

Jev, explained simply

Full longer version: v5. Short cut: three questions. Comments on v7 applied here.

A normal pretrained LLM that reads your input once and, instead of writing words, scores the options you gave it — trained so the scores are honest probabilities.

1. How is Jev actually built?

Community reconstruction from TypeSafe docs, Archer Hume's API probe, and the open clones that appeared in 48 hours.

High-level stack (transformer + head + RL)

RLCD RLCD objective reward honest probabilities “0.8 bucket ≈ 80% right” Still secret loss, data, base id dense vs MoE PROBE CHECKS (NOT CROPPED TEXT — READ THESE) Sibling-question secret → 0.00 · same secret in state → 0.90–0.92 · 1,500 Qs ≈ 610 ms · latency flat 2→255 options · ECE 0.031 on 1,200 MMLU · tokenizer ≠ any of 192 public ones

Inference is “encode once → score options.” Training is “make those scores calibrated.” The open clones copied the middle diagram shape; they did not copy RLCD or 64k context.
